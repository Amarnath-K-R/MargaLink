# `/write` becomes the hub — Implementation Plan

> Executed natively (superpowers:executing-plans), one commit per task, `cd web && npm run check`
> green before every commit; a task that changes a smoke also runs that smoke against `npm run dev`.
> Commits `Hub (n/10): <what>`; push; never merge to `main`. Task 0 copies this plan to
> `docs/superpowers/plans/2026-09-27-write-hub.md` and a short spec to
> `docs/superpowers/specs/2026-09-27-write-hub-design.md`.

**Goal:** `/write` becomes the hub: from one page a researcher writes the paper, matches it to
journals, sets a target journal and reads its rules, checks format and rules, makes and inserts
figures, and gets the AI review, each tool opening in a pop-up window over the workspace.

**Architecture:** the three tool pages' wiring is lifted into hooks (`useMatch`, `useReview`,
`useFigures`) that both the standalone pages and the workspace consume; `Workspace` holds the tool
state and renders one native `<dialog>` whose body is a dynamically imported window; the paper text
for Match/Review/Checks is the last compiled PDF through the existing `extractFromFile` pipeline;
pure LaTeX-source helpers live in one selfchecked module `texSource.ts`.

**Tech stack:** Next.js static export, React 19, Tailwind v4, CodeMirror 6, native `<dialog>`,
`next/dynamic`, OPFS (`projectStore.ts`), Playwright smoke, `node`-run `*.selfcheck.ts`. No new npm
dependency.

**Spec:** `docs/superpowers/specs/2026-09-27-write-hub-design.md`.

## Context

`/write` is the product's core: a researcher should write a paper start to end and reach every
other tool from inside it. Today it is a fixed three-column page (file tree · CodeMirror · PDF
iframe) with one "toolbar" row (back, name, engine, Compile) and one cross-tool bridge (`/figures`
→ "Add to a paper"). Match, review, figures and journals each live on their own page with their
wiring locked inside `page.tsx`.

**Owner's decisions (2026-09-27):** keep the layout — toolbar on top, files on the left, LaTeX and
PDF side by side — and open each tool in a **pop-up window** over it. A window's state must survive
closing it (close Match, keep editing, reopen: results still there). **No AI writing helper** in
this plan; the only network-sending features stay the existing two (AI review, figure "Ask
Claude"), behind their existing consent components. Standalone tool pages remain.

**Outcome:** from one page: write → see which journals the draft fits → set a target journal → read
its rules and get its template → check format/rules → make a figure and drop it in at the cursor →
get the AI review with "jump to source" → all with a per-project URL, a command palette, an Insert
menu and a status bar that says plainly what (if anything) was sent.

## Decisions (one-line trade-off each)

1. **Paper text for Match/Review/Checks = the last compiled PDF** → `extractFromFile(new File([pdf], "…pdf"), {headings:true})`. Reuses the pipelines exactly as tuned (headings by font, references from the bibliography). Cost: a window says "Compile first" until there is a PDF. A LaTeX→text detex is deferred; only a ~25-line `texWordCount` detex exists, for the status bar.
2. **Dialog = native `<dialog>.showModal()`** (`src/components/Dialog.tsx`, ~50 lines): focus trap, Escape, `aria-modal`, top layer and focus restore for free. No dep.
3. **No minimize chip; state survives close.** A status-bar "running" chip (Reviewing 3/7…) reopens a tool mid-run. Closing a window never aborts a run (a review costs quota).
4. **Shortcuts: Mod-S (exists), Mod-K palette, Escape.** No Mod-1..5: browsers reserve Ctrl/Cmd+digits for tabs.
5. **Insert menu = native `<select>` with `<optgroup>`s** (the workspace's existing "Insert figure" pattern): keyboard + a11y + hundreds of bib keys for free. Looks like a select, not a menu; acceptable.
6. **Editor/PDF split is resizable** (`role=separator` handle → CSS var, ~30 lines, ratio in localStorage). Phone layout untouched.
7. **Hooks live beside their tool** (`match/_components/useMatch.ts` etc.); `/write` imports across routes (noted in ARCHITECTURE). Pages become JSX over their hook, no behaviour change; their smokes must pass unchanged.
8. **"Use its template" creates a new project**, never mutates the open one (class swaps break compiles). `Workspace` gets `key={openProject.id}` so tool state can't leak between projects.
9. **`ProjectMeta.journalName?`** added so the toolbar chip needs no 5 MB `loadMeta()`; old projects show "Target journal" until resolved.
10. **Figure recipes** `figures/<name>.figure.json` = `{version:1, spec, hook}` (data-free, same shape as `RecipeImportExport.readRecipe`) saved beside the PDF so a figure can be reopened.
11. **Each window extracts its own text** (≤3 `extractFromFile` per compile, ~0.5 s each). Fix on the way: `extract.ts` never calls `doc.destroy()` (leaks a pdf.js worker per extraction).

## What the user sees

**Windows** (all `Dialog`; bodies via `next/dynamic({ssr:false})` so pdf.js/transformers/figure code load only when opened):

"Jump to source": `findQuoteInTex` over the live doc then `sources` → closes the window, opens the file, `editor.goto(line)`; else `role=status` "Couldn't find that passage in the source." Draft changed → "Load the new draft" (explicit, so a finished review isn't discarded).

"Edit in the figure studio" button appears above the editor when a `*.figure.json` is open → `pendingRecipe` → applied once a dataset is attached (`readRecipe`). Pyodide loads only after a spreadsheet is attached inside the window. Insert disabled while compiling (memory peaks don't overlap).
- **Checks** (`lg`, `data-testid="checks"`): auto-runs `checkFormat` + `checkRules(rules)` over the PDF text when stale; `FormatCheckPanel` + `RulesCheckPanel` or "Set a pilot journal as the target to check its rules."
- **Journal** (`lg`): `JournalDetail` (from `loadMeta()`/`loadTopicNames()`, cached module vars) · rules (`findJournalRules`, `REQUIRED_STATEMENT_LABELS`, guidelines link, "as published on {asOf}") or "No hand-verified rules yet" + homepage · template via `templateForJournal(host, templates)`: bundled → "Start a new paper from it" (`create(t, journal)`, opens it); link-only → publisher link + import hint · "Change journal": `<input aria-label="Search journals">` over `loadMeta()` (same filter as `journals/page.tsx`), first 20 rows, "Clear target" · no journal: search + "Or match your draft".
- **Command palette** (`md`): `<input data-autofocus aria-label="Search commands">`, `role=listbox`, Arrow/Enter; commands: Compile, open each window, Insert table/equation/section, each project figure, Rename, Download backup, Download PDF, switch engine, All projects.

**Every paper-reading window when `pdfFile === null`:** "Compile the paper first — these read the compiled PDF, on this device." + Compile button (disabled while compiling).

**Per-project URL:** `/write?p=<id>` read on mount (`s.meta(pid)` → open), written with `history.replaceState` when a project opens/closes; `?journal=` keeps working for new projects. `AddToPaper` on `/figures` links "Open it in the workspace" → `/write?p=<id>`.

**Phones:** unchanged (last PDF only); tool buttons/palette are `md:`-only.

```ts
export function texWordCount(tex: string): number;   // drops comments, preamble (before \begin{document} if present), math, \cite/\ref/\label/\includegraphics; keeps brace contents
export function bibKeys(bib: string): string[];      // @type{key, | @type(key, ; skips @comment/@preamble/@string; unique, in order
export function texLabels(tex: string): string[];    // \label{…} outside comments; unique
export function findQuoteInTex(tex: string, quote: string): number | null; // 1-based line; see algorithm
export function figureSnippet(path: string): string; // today's snippet (Workspace.tsx:25, AddToPaper.tsx:8), \label{fig:<slug>}
export function nextFigurePath(existing: string[], base = "figure"): string; // figures/figure.pdf, figures/figure-2.pdf…
export const SNIPPETS: { table: string; equation: string; section: string };
export const citeSnippet = (k: string) => `\\cite{${k}}`; export const refSnippet = (l: string) => `\\ref{${l}}`;
```
`findQuoteInTex`: normalise each line (strip `%` comments; drop `\cite{}`/`\ref{}`/`\label{}`; unwrap `\cmd[opt]{X}`→`X` up to 5 passes; drop bare `\cmd`; lowercase; non-alphanumerics→space; collapse), join with spaces recording line start offsets; normalise the quote the same way; needle = first 6 words of ≥3 letters (fallback last 6); `indexOf` → the line whose start offset is the largest ≤ index; else null.

## Review Focus

1. **No compile yet / stale PDF** → "Compile first" in every paper-reading window; `hook.source !== pdfFile` drives "Draft changed" (Match), auto re-run (Checks), explicit "Load the new draft" (Review).
2. **No `.bib`, no labels, main without `graphicx`** → Insert omits empty groups; graphicx hint; smoke inserts into the `article` project (IEEEtran only comments out `\usepackage{graphicx}`).
3. **Target journal not a pilot, or none** → Review shows picker + explanation; Checks runs the format check only and says why; Journal shows details without rules; `findJournalRules` accepts the full OpenAlex URL via `shortId`.
4. **Closing mid-run / quota exhausted mid-run** → closing never aborts (state in Workspace's hook; chip reopens); Cancel explicit; `ReviewLimitError` surfaces on reopen; use counted once.
5. **Pyodide + TeX + pdf.js in one tab** → Pyodide loads only after a spreadsheet is attached; Insert disabled while compiling; `doc.destroy()` in extract; both runners respawn on timeout.

Also: `key={openProject.id}` on `<Workspace>` (tool state must not leak between projects); `compile-status` must contain only the status string.

## Risks and deferred

- "Compile first" is a real step for Match/Review/Checks; a LaTeX→text detex could remove it later (own spec).
- Review remains limited to the 8 pilot journals (data, not code).
- The figure window is heavy (Pyodide); memory with TeX in the same tab is mitigated, not measured.
- Deferred (unchanged from the write spec): AI writing help, SyncTeX, DOI→BibTeX, co-editing; FileTree `prompt/confirm` → Dialog; a real menu for Insert.
